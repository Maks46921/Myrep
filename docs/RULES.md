# Постоянные правила проекта Symphony (от заказчика)

1. **Новая механика — для каждой страны.** Любое нововведение (окно, закон, событие, слой карты, экономика, выборы…)
   должно работать во ВСЕХ странах пакета (сейчас 38 — список `COUNTRY_CODES` в `scripts/data/data_core.gd`) и учитывать
   их особенности (монархия/республика, система выборов, число мест, палаты, регионы). Общий код + данные по странам.
2. **Новая страна — со всеми прошлыми нововведениями.** При добавлении страны проверить чек-лист ниже.
3. Если пользователь просит новое и что-то из 1–2 не выполнено — выполнить это в той же версии.
4. Пользователь — начинающий, отвечать по-русски; к каждой просьбе можно добавлять немного от себя; если сообщение слишком большое
   или нужна информация — сохранить работу в файл, чтобы продолжить.
5. Доставка версии: `Symphony_vN.zip` (папка проекта целиком: project.godot, main.tscn, main.gd, scripts/, tests/, tools/, docs/),
   в /mnt/user-data/outputs; старый zip удалить; кратко по-русски, честно что проверено. Запуск: Godot 4.3 → Import → project.godot → F5.

## Недельный расчёт (0.62)
Игра считается не раз в месяц, а понемногу каждую неделю. Календарь по дням остаётся; недельные тики идут 8-го, 15-го и 22-го числа
(`week_tick()`, доля месяца `dt = 7 / дней в месяце`), а на границе месяца идёт «закрывающий» шаг (`next_turn_core()`) с оставшейся
долей месяца (≈0,3). Так в каждом месяце ровно 4 шага: три недельных и один закрывающий, последняя «неделя» 7–10 дней.
Тесты и старый путь зовут `next_turn()` напрямую: тогда недельных тиков не было и шаг один, с `wdt = 1.0`.

**Две переменные и три помощника** (`state.gd`, `turn.gd`):
- `wdt` — доля месяца в текущем шаге: 1.0 (месячный шаг без тиков), ≈0,23 (недельный тик), ≈0,3 (закрывающий шаг после трёх тиков).
- `wmonth` — шаг закрывает месяц (true в месячном шаге и при `next_turn()`; false в недельном тике).
- `wp(p)` — вероятность события за шаг, если за месяц она `p` (при `wdt == 1.0` возвращает `p` без изменений);
  `wr(r)` — доля сближения к цели за шаг, если за месяц она `r` (то же, что `rt(r, wdt)`); линейный прирост: `x += c * wdt`.

**Как переводить подсистему** (функция `X_month()` → `X_week()`):
1. Разделить тело на (а) непрерывную динамику и случайные события, (б) дискретное (счётчики и сроки в целых месяцах, записи в журнал
   «за месяц», `turn % 3 == 0`, годовые итоги). Часть (а) масштабируется на `wdt`, часть (б) выполняется только при `wmonth`.
2. Скорость сближения `x += (цель − x) * k` → `k = wr(k)`; линейный прирост `x += c` → `x += c * wdt`; вероятность `randf() < p` → `randf() < wp(p)`;
   «каждые N месяцев» остаётся дискретным (при `wmonth`).
3. **При `wdt == 1.0` и `wmonth == true` результат должен быть тем же, что у старой функции, бит в бит, включая порядок вызовов `randf()`**:
   тогда эталоны `tests/golden` не меняются. Проверка: `python3 tools/test.py golden` без `--update`.
4. Зарегистрировать функцию в `WEEK_HOOKS` (`scripts/logic/turn.gd`, в своей секции). Месячный шаг продолжает звать её сам (с `wdt` = остаток месяца).
   Если переведена только часть тела, остальное остаётся в старой функции под `if wmonth`.
5. Журнал: недельный тик не должен писать строки чаще, чем раньше (4× больше сообщений недопустимо). Пишите в журнал при `wmonth` или по порогу.
6. Сверка с месячным расчётом: `python3 tools/wk_ab.py -c DE,FR -s 7,8 -y 5` печатает отклонение недельной игры от месячной (допуск заказчика:
   ВВП за 10 лет в пределах 7 %, остальные показатели близки; для своей подсистемы добавьте показатели в `tests/dev/wk_ab.gd`).
7. Время работы: `week_tick` вызывается 3 раза в месяц; тяжёлая подсистема (сотни мс) должна считаться дёшево или быть сделана инкрементально.
   Цель заказчика: игровой месяц ≈ 2 с на обычном игровом ПК (у облачной среды вдвое-вчетверо медленнее).

## Чек-лист новой страны (все пункты обязательны)
- пакет данных в `scripts/data/data_countries.gd` (CDATA): партии (10 слотов), регионы, законы, события, мир (см. docs/SPEC_NEW.md);
- `ELEC_DATA` (scripts/data/data_core.gd): система выборов, явка, примечание, тип главы государства (direct/indirect/council/monarch)
  и, если выборный, поля title/title_n/term/first (+ body/ele_x/ele_add/need/secret для indirect);
- региональная экономика: у регионов появляются поля состояния (smul/zones/migr/rdebt…) автоматически; проверить `REG_EVENTS_CC[код]`
  (региональные события страны) и слои карты 0–26;
- радикальные законы: страна должна быть в RAD_MONARCHIES (если монархия) и иметь RAD_CUR, темы из RAD_AUTH_TOPICS (если есть свои);
- полукруг парламента строится из SEATS автоматически (ElectionView.hemi_layout) — тест `head` (отношение ≥ 1.0);
- население-агенты: ничего настраивать не надо при корректных LEAN, REGIONS (sec, popm, mix); тест `agents` (расхождение < 1 п.п.);
- `GOODS_OVR` (множители долей товаров с учётом местных привычек, см. раздел «Товары») и `MARKETS_OVR`;
- страна автоматически появляется на карте выбора (нужны её единицы в WORLD_UNITS и записи в WORLD/CDATA[INFO]);
- в `tools/test.py` добавить код страны в ALL; создать эталон: `tools/test.py golden --update -c XX`;
- тесты: `tools/test.py full -c XX` — все зелёные.

## Население-агенты (v19)
- `scripts/classes/agent_pop.gd` + `scripts/logic/agents.gd` + `scripts/ui/ui_pop.gd`: 1 агент = k человек (авто: население/40 000, 100–1000).
- Партии получают идеологические позиции автоматически из состава электората (`LEAN` × центры групп).
- Голосование (`region_shares`) и опросы идут по агентам; выборы — по всем, опросы — по выборке; на старте результат совпадает с прежней моделью
  (`ag_calibrate`).
- 0.62, недельный расчёт: `ag_step` стоит в `WEEK_HOOKS`. При `wdt == 1.0` (месячный шаг без тиков) работает прежний путь: шаг по агентам `AG_STRIDE` = 4,
  `months` = 4. В недельном расчёте на месяц приходится 4 вызова, поэтому шаг по агентам `AG_STRIDE_W` = 16 (`AgentPop.step(..., mscale)` с `months` = 4):
  каждый агент по-прежнему обновляется раз в 4 месяца с теми же коэффициентами, а нагрузка за месяц не выросла (на вызов вчетверо меньше агентов).

## Товары (v22)
- 18 видов товаров и услуг (`GOODS` в `state_data.gd`) стоят поверх шести рынков: каждый товар привязан к рынку-поставщику (`mk`), доли `kg` в сумме дают долю рынка в корзине.
- Цена товара (`ec["gp"]`, относительно общего уровня цен) = цена рынка × `ps` + курс (`xf`) + пошлины (`tf`) + мировое сырьё (`dc`) + НДС (`vat`) + разовые шоки (`ec["gsh"]`) + медленный дрейф (`dr`). Спрос (`ec["gd"]`) зависит от дохода (`ie`) и цены (`pe`) и входит в спрос рынка.
- `cpi_idx` считается по корзине товаров и снижает покупательную способность (`ppi`).
- Корзина группы = `GOOD_PROF[группа]` × доли товаров. Если корзина группы дорожает сильнее средней, падает её поддержка (`goods_support_term` в `target_support`).
- Агенты: у каждого свои доли расходов (группа + возраст + доход, `AgentPop.gw`); цены своей корзины сдвигают его оценку власти (`zg`, `AG_GK`).
- Страна: `GOODS_OVR` в `data_countries.gd` (множители долей; сумма по рынку нормируется `apply_goods()`). **Новая страна обязана иметь `GOODS_OVR`.**
- События и меры: `fx["econ"]["g"] = {товар: сдвиг цены}`.
- UI: «Экономика» → «Товары и цены» (desk 7). Тест: `tools/test.py goods`.

## Крупные данные вне скриптов (v23)
- `CDATA` (пакеты стран), `WORLD`, `WORLD_UNITS` лежат в `data/countries/XX.dat`, `data/world.dat`, `data/world_units.dat` (текст в формате `var_to_str`, читается `str_to_var` через `ext_load` в data_core.gd).
- Причина: строки по 40 000+ символов в .gd вешали редактор Godot. НЕ возвращать большие литералы в скрипты (держать строки < ~2000 символов).
- Правка данных: открыть .dat в любом текстовом редакторе (не в Godot) или загрузить, изменить и записать `var_to_str` (см. tools/extdump.gd как образец). Новая страна: добавить файл `data/countries/XX.dat` и код в `COUNTRY_CODES` (data_core.gd).
- При экспорте проекта добавить фильтр `*.dat` в «Resources → Filters to export non-resource files».
- `tools/datagen_legacy` и `docs` помечены `.gdignore` (редактор их не сканирует).

## Федерация, автономия, территории (v26)
- Логика — `scripts/logic/federation.gd` (в цепочке после world.gd), интерфейс — `scripts/ui/ui_fed.gd` (вкладки карты «Регионы и автономия» = desk 8 и «Территории» = desk 9). - Передача территории: `terr_buy`/`terr_sell` (регион соседней страны) и `union_do` (добровольное объединение стран). Все параллельные массивы регионов (REGIONS, regions, reg_mix, reg_cd, loy_off, unr_off, REG_BIAS, table_order) меняются ТОЛЬКО в `fed_take_unit` / `fed_drop_region`, затем `fed_rebuild()` (геометрия, веса, карта, агенты, виджеты). Принадлежность единиц карты — `WORLD_UNITS[ui]["cc"]`; резервная копия в `fed_u0`/`fed_w0`, `fed_reset_world()` возвращает мир в исходное состояние.
- Любой региональный идентификатор берётся из `REGIONS[i]["uid"]` (например "DE-BW"), а не из ccode + code — у купленных регионов код чужой страны.

- **Оппозиция**: если выбранной партии нет в стартовой коалиции или вы проиграли выборы, включается `opp_mode`: правительство без вас (`opp_gov`), бюджет и министерства у них (ползунки заблокированы, автопилот баланса включён принудительно), поддержка вашей партии = база − 0,6·(оценка власти − база) (`target_gov_support` / `target_support`). Действия `OPP_ACTS` (критика, митинги, расследование, досрочные выборы, вотум недоверия, вход в коалицию) — экран «Политика → Оппозиция и сделки» (desk 12). После выборов `opp_after_election` возвращает власть, предлагает коалицию (спец. событие «offer») или оставляет в оппозиции. Поражение у власти (чужое большинство и вы не сильнейшая) → `opp_enter` вместо конца игры.
- **Соглашения партий** (`PACT_KINDS`, `prel`, `pacts`): переговоры (+отношения), предвыборный блок (+голоса), поддержка (`tolerates`), союз по голосованию (`variant_votes`), публичная атака. Отношения влияют на `willingness`.
- Карта: у неигровой страны обводится вся страна, у региона — регион; клик по далёкой стране без соглашений не падает (`dip_far_box`).
- Бюджет: «Автоподъём расходов до минимума» (`auto_floor`), субсидии разделены на бизнес и аграриев.
- Гибридные законы: вариант + сила действия (`HYBRID_IDS`, `law_pow`); финансирование партий — гибридный закон, влияет на голоса (`funding_mult`).
- Время: кнопок пропуска нет, только скорость течения.
- Тесты: `opp` (смена партии на нескольких странах, старт в оппозиции, действия, соглашения, переходы), `far`, `budget`, `hybrid`.

## v32 (партийный ИИ)

Модуль `scripts/logic/aiparty.gd` (после `opposition.gd`).
- **Идеологии** (`ARCH`, `ideo_*`, `party_arch`): идеология партии выводится из её электората (`LEAN` × `GROUP_FX`): чего хочет электорат от бюджета, то партия и считает своей политикой. Архетипы: левая, либеральная, консервативная, зелёная, популистская; у каждого `aus` (экономия), `bold`, `aggr`, `coop`. Это работает в любой стране без отдельных данных.
- **Верность линии игрока** (`idl`, `idl_planks`, `idl_step`): у выбранной партии до 5 принципов (какие бюджетные статьи увеличивать/сокращать). Курс против принципов снижает `idl` (множитель капитала `idl_mult`), при `idl<20` три месяца подряд партия отстраняет вас. Союзы с идеологически далёкими партиями тоже снижают верность (`idl_react`).
- **Младший партнёр** (`junior_info`): если в вашей коалиции есть партия крупнее, власть = 0.35+0.9·доля мест (0.4–0.85): меньше капитала, бюджет меняется не больше чем на 10%·власть диапазона в месяц (`lock_allowed`), закон не проходит, если партия главы правительства против (в `adopt_variant`).
- **Правление неигровой партии** (`ai_gov_rule`, `ai_policy_step`): в оппозиции программа правительства = средневзвешенная идеология партий коалиции; каждый месяц ползунки сдвигаются к ней (расходы всегда, налоги — если есть запас по дефициту). Автобаланс корректирует налоги.
- **Капитал партий** (`pcap`): прирост от веса в парламенте и власти; тратится на законопроекты, атаки, переговоры, блоки. Автопилот в оппозиции тратит капитал главы правительства (`cap_swap`).
- **Отношения партий** (`prm`, `rel`, `rel_add`; строка 0 — это `prel`): партии дружат с близкими, атакуют соперников, заключают предвыборные блоки (`ai_blocs`), давят на ваше правительство или на правительство без вас. Правительство без вас теряет партнёров (`sat`), вербует новых, меняется без выборов (`ai_reshuffle`), падает при потере устойчивости.
- **Действия игрока над партиями** (`PACT_KINDS`, поле `cls`): дружеские (переговоры, похвала), поддержка (блок, терпимость, союз по голосованию, помощь ресурсами), враждебные (атака, компромат, «нерукопожатность»).
- **Законопроекты** (`propose_variant`, `bills_step`, `bill_request`, `bill_amend`): закон не принимается в один клик — вносится (взнос 35% капитала), идёт 3 мес. (5 для фундаментальных), партии присылают просьбы о поправках (смягчить, отложить, уступка за капитал), вы можете смягчить/усилить, купить голоса оппонентов, ускорить, отложить, отозвать. В конце — голосование через прежний `adopt_variant`. ИИ-правительство вносит свои законопроекты, проверив голоса заранее.
- Интерфейс: «Политика → Оппозиция и сделки» (идеология, действия, сделки), «Законы» → окно «Законопроекты и поправки».
- Тест: `python3 tools/test.py ai -c DE,LU,...` (идеологии, курс правительства, капитал, длинная дистанция 96 мес., законопроекты, младший партнёр, верность линии).

- **ИИ**: атакует там, где рядом собран перевес ≥ 1,15; соседние свободные части поддерживают атаку или подкрепляют атакованную
  свою АТЕ; при перевесе гонится за прорвавшимися соединениями и освобождает свою землю; потрёпанные части (организация < 0,35)

- Экономика войны: мобилизация снижает рост, война стоит ВВП × 0,25% + 0,004 × тыс. солдат в месяц, влияет на инфляцию, безработицу,

### Два языка (tools/i18n.py, boot.gd)
- Игра по-прежнему пишется **по-русски**: все тексты — строковые литералы в `main.gd`, `scripts/**` и `data/**.dat`. Проверка разбора английского дерева: `godot --headless --path . --script tools/chk_parse.gd -- en`. Тесты английской версии: `tools/test.py quick --en` (логи `.testlogs/en_*`).

## 0.57.1 (голосование, повестка, последствия законов)
- **Окно голосования** (`ui_vote.gd`) имеет два этапа: 1 — выбор стратегии (`vote_plan_open(bid)`, `vote_plan_refresh()`, `vote_plan_go()`), 2 — зал и итог (`vote_show()`). `vt_stage`: 0 нет, 1 выбор, 2 итог, 3 голосование идёт. `vote_plan_live()` — только в живой игре (не наблюдатель, не автопилот событий; в тестах включается `game_opts["voteplan"]`); без него всё идёт по-старому, поэтому симуляции и эталоны не меняются. `vt_plan_busy()` — окно выбора открыто.
- **День голосования** (`aiparty.gd`): `bills_step()` вызывает `bill_warn_short(b)` и, когда срок пришёл, при `bill_plan_wanted(b)` открывает окно и пропускает законопроект (время стоит); после закрытия итога `bills_due_step()` подхватывает остальные. Само голосование — `bill_run_vote(b)` (`bill_vote`, `pa_bill_vote`, `ai_bill_vote`). Флаг `b["go"]` — игрок выбрал, `b["warned"]`, `b["traded"]`, `b["amended"]` (поправка силы чужого закона; `pa_bill_vote` и `ai_bill_vote` берут `b["pow"]` только если `amended`).
- **Стратегии своего законопроекта:** `bill_swing_parties`, `bill_deal_cost`, `bill_press_ok/bill_press_cost`, `bill_plan_preview(b, extra, pv)` (чистый прогноз), `bill_plan_apply(bid, deals, press)` (списывает капитал, добавляет партии в `forced`, пишет `vote_notes`). **Чужого:** `pa_set_vote` (линия фракции), `pa_trade`, `pa_amend`.
- **`last_vote`** пополнился полями `notes` (пометки к фракциям: `vote_notes`), `next` (текст «Что будет дальше», считается до применения закона `vote_next_text`), `noconv` (закон не вынесен на голосование: окно показывает прогноз и «ОТКЛОНЁН»). `vote_show()` больше не пропускает чужие законопроекты (пропуск остался для режима наблюдателя и тестов).
- **Зал:** `vote_layout_seats()` подбирает число рядов так, чтобы шаг между рядами был равен шагу между местами (`vt_tile`); `vote_draw()` рисует плитку в цвет партии, кружок голоса и белую рамку отступнику; анимация `VT_ANIM = 2.0`.
- **Повестка:** `bills_attention()` (sev 3 просьба, 2 не хватает голосов, 1 чужой законопроект без решения фракции) питает карточки (`bill_cards_build`, `bill_make_card` в `ui_opp.gd`), точку на вкладке «Политика» (`nt_dot_state`) и строку в «Сегодня». Подпись карточек перестраивается только при изменении подписи состояния (`bill_sig`). Положения окон экрана «Законы» заменены; сохранённые прежние положения по умолчанию переносятся (`LAY_MIGRATE`, `ui_nav.gd`).
- **Последствия закона:** `variant_effect_items()` сравнивает `compute_mods(кандидат)` с `compute_mods(law_state)`, а не с живыми `mods`; `mod_visible()` скрывает сдвиги, которые округляются до нуля; `mod_channel()` подписывает канал. Правило для новых мест, где игра сравнивает «с текущим состоянием»: брать чистую функцию `compute_mods`, а не `mods`.
- **События:** цена в капитале только на кнопке (`events.gd`: `fx_no_capital`, `strip_capital_note`).
- **Тесты:** `tests/vote_ui.gd` (снимки окна: `kind=own|other tid= idx= mode=0|1|2 out=`), `tests/audit_items.gd` (что показано в последствиях закона), `tests/audit_laws.gd`, `audit_law_sim.gd`, `audit_names.gd` (сверка законов).

## 0.57.2 (последствия законов, формула роста, растянутые региональные сдвиги)
- **Рост от потери демократичности:** `compute_mods()` в конце добавляет к `growth_bonus` значение `DEM_GROWTH_CAP * clamp((dem_shift + 0.15) / 0.45, -1, 0)` (`policy.gd`). Прямых `growth_bonus` у форм правления, конфедерации и теократии нет: не добавлять новые.
- **Последствия закона:** элемент `variant_effect_items()` может иметь третье поле (подсказка). `items_pros_cons()` оборачивает такой элемент в `[hint=...]`; текст подсказки не должен содержать `]`. Показатели `sec_bonus/security_lvl`, `corr_shift/corruption`, `equal_shift/equality` сливаются одной строкой (`MERGE_STAT`). Разброс считается из `CHAN_WIDTH` (канал) и `range_factor()` (коррупция страны); `NO_RANGE` перечисляет точные показатели. Разброс только подпись, расчёты игры его не используют.
- **Региональные сдвиги закона** (`rg`) копятся в `rg_drip` (состояние) и применяются по 1/12 в месяц функцией `rg_drip_step()` (вызов из `bills_step`). Сброс в `init_laws()`.
- **`rgrel`** (в `fxnow` варианта): сдвиг региональных показателей, умноженный на `reg_rel_k(i)` (в регионах с меньшей долей села и пенсионеров реакция сильнее).
- **Барьер:** `thr_party_info(thr)` по `national_shares(false)` считает число партий и долю потерянных голосов для окна последствий.

## 0.58 (места по методам, пороги законов, суд, референдум)
- **`allocate_seats(shares)`** (elections.gd): метод по `ELEC.alloc` (`hare` по умолчанию, `dhondt`, `sl`, `fptp`, `two_round`, `stv`), магнитуда `ELEC.mag`, региональный порог `ELEC.thr_reg`, округа — регионы игры (`regional_seats`, места между регионами по `pop_w`), смешанные системы `ELEC.smd` + `smd_reg`/`smd_method`/`k` (степень «закона куба»), бонус `ELEC.bonus_rule` (Греция), гарантированные места `MACRO.reserved = {слот: мест}`; `nat_raw_cache` хранит национальные доли до барьера.
- **`parl_shares()`**: слот 6 («Прочие») барьер не проходит, если `thr >= 0.005`, кроме стран с `MACRO.others_pass` или `thr_exempt`; `thr_party_info()` (laws.gd) считает так же.
- **Президентский второй тур**: сжатие 0,85, штраф «кордона» 8 п.п.; `ELEC.round1_reg` — победа в 1-м туре по доле зарегистрированных (Северная Македония).
- **Календарь Швеции:** `MACRO.fixed_cycle`; **«медовый месяц»:** `gov_born` (месяц формирования правительства), множитель в `vote_weights()`.
- **`law_need(tid, v)`** (laws.gd): конституционные — `ceil(SEATS * MACRO.const_need)` (по умолчанию 0,667), органические (`ORGANIC_IDS`) — `MAJORITY`, обычные — `max(против + 1, SEATS/3)` (не больше `MAJORITY`) либо `MAJORITY`, если `MACRO.law_all`. Воздерживаются партии, терпящие правительство (`tolerates` или договор `tol`), если закон им неприятен и позиция не хуже −2.
- **`FUND_IDS`** сокращён; `DE_FUND_ADD` по умолчанию `["debt_brake", "eu_policy"]`, списки стран очищены.
- **`upper_check`**: для `override`/`consent` конституционный закон требует согласия верхней палаты (`fund_bind`), кроме GB, IE, SI.
- **Референдум** `MACRO.amend_ref` (IE, CH, RO, DK): доля «за» из `national_shares` и позиций партий, шум 3 п.п.
- **Суд:** `court_chance(tid, idx)` и `REVIEW_STRONG`; основа 12 %, растёт с независимостью судов (`rl_jud()`), для законов со сдвигом демократии ниже −0,05 умножается на 1,8.
- **Вотум недоверия:** `noc_constr` пересчитывается в `recompute_mods()` из `mods["constr"]`; `resolve_no_confidence()` берёт порог из `impeach_seats()`; при конструктивном вотуме — `ai_form_gov(false)` и `opp_enter()` без выборов.
- **Роспуск:** `dissolve_blocked(reason)` / `no_dissolution_outcome()` для стран с `SNAP_RULES[..][2] < 0` (NO, BA, CH); `snap_info()` блокирует роспуск в последние 6 месяцев мандата президента (IT, PT); новые `SNAP_RULES` для MD, UA, BY, RU.
- **Польша:** `UPPER["veto_p"]` меняет номер вместе с `swap_idx` в `apply_player_party`.
